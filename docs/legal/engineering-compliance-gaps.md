# Birdfolio 工程合规缺口清单（商业发布前草案）

> 草案，需在正式发布前由专业人员复核。

版本：`0.1-draft`
核对日期：2026-11-08
核对基线：`origin/main@e07e3d1`

本清单只记录需要工程实现或验证才能兑现的条款，不表示已完成法律合规评估。优先级用于发布准备，不等同于法律风险结论。

## 1. 当前事实

- HarmonyOS 客户端支持游客本地使用；邮箱登录后可使用云同步、AI 和社区相关能力。
- AI 图片在本地授权后上传至 Birdfolio 后端，再转发给配置的 OpenAI-compatible 视觉服务；不宣称自研模型或科研级准确率。
- 后端使用 SQLite 和本地媒体目录；开发入口为 HTTP。
- 正式 HTTPS、邮件网关、生产部署、备份恢复和管理员后台未完成。
- `fuzzyLocation` 当前只是字段标记，不会自动模糊坐标。
- 服务端已有举报和屏蔽 API，但客户端没有可验证入口，管理员处置流程也未实现。
- 诊断偏好只在本地保存，未发现诊断上传；但现有 `hilog` 可能直接输出精确坐标、地点名和文件 URI/路径。

## 2. 发布阻断项

| 优先级 | 缺口 | 当前不一致或风险 | 完成标准 |
| --- | --- | --- | --- |
| P0 | 生产传输与部署 | 开发服务使用 HTTP，不能兑现生产安全传输 | HTTPS 终止、强制跳转、受限 CORS、认证、限流、密钥管理和部署基线通过安全验收 |
| P0 | 真实邮件投递 | 邮箱验证码生产网关未配置 | 接入实际邮件服务，完成供应商披露、失败处理、反滥用和投递监控 |
| P0 | 敏感位置保护 | UI 有“区县级概览”提示，但代码不转换精确坐标 | 服务端强制降精度/移除、敏感规则库、延迟发布、访问审计及自动化测试完成 |
| P0 | 日志最小化 | `hilog` 使用 public 占位输出精确经纬度、地点名和文件 URI/路径 | Release 构建不输出上述信息；完成日志分类、脱敏、开关和保留验证 |
| P0 | 社区治理闭环 | 只有举报/屏蔽 API，没有客户端入口和管理员后台 | 用户可举报/屏蔽/解除屏蔽；管理员可处置、通知、审计和处理申诉 |
| P0 | 数据保留与删除 | 媒体过期值没有自动物理清理；其他数据无批准期限 | 按数据类别实现自动清理、失败重试、删除审计、备份过期和第三方删除转交 |
| P0 | 账号注销语义 | 注销后仍保留邮箱等用户字段，同邮箱登录会重新启用原 ID | 经专业评估决定物理删除、匿名化或必要保留；界面、政策、测试与实现一致 |
| P0 | AI 供应商确认 | 实际供应商、地区、留存和训练政策未知 | 供应商合同与数据处理条款完成，应用内说明和隐私政策填入 `[待确认]` 项 |

| P1 | 诊断控制 | 诊断开关未连接实际采集/日志流程 | 明确“不采集”或实现真正的用户控制、最小化、上传告知、删除和保留规则 |

## 5. 必须增加的测试与验收

1. 未同意 AI、已撤回 AI、未登录三种状态均不得读取并上传识鸟照片。
2. AI 只能返回候选，未经用户确认不得创建观察。
3. 定位拒绝后仍能保存无坐标记录；同步和社区不会意外泄露精确位置。
4. 敏感位置处理对客户端篡改和直接 API 请求同样有效。
5. 账号注销覆盖观察、社区、媒体、AI、同步、会话和备份，并验证失败重试。
6. 数据导出内容与隐私政策列举范围一致，不遗漏也不越权导出。
7. Release 日志不包含 Token、邮箱、精确坐标、地点名、图片 URI/路径或 AI Key。
8. 社区举报可达、可追踪、可处置、可申诉；无管理员时不伪造处理状态。
9. AppGallery 权限扫描结果与 `appgallery-data-and-permissions-inventory.md` 一致。
10. 第三方素材随机抽样可追溯到作者、许可证和来源。
